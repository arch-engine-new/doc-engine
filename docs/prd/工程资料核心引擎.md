> sourceDoc：`docs/智能工程资料管理平台-核心引擎-两周实现计划.md`（范围冻结，只增不减）  
> 风格：`apt-skyline-clean`  
> 最终实现：Vue 3 + Vite + TypeScript；本文配套 HTML 原型仅供 PM 预览

## 产品定位 / 摘要

**productSummary：** 工程资料核心引擎：教用分离。系统提供模板标注、规则运行时、待审与组卷预览；不预置任何行业规则。正式写库只认中台回执。

配置人员「教」引擎（规范包、模板框、DSL、标准库）；操作/审核人员「用」引擎跑流水线。验收只验引擎能否被教，不验某个专业管得对不对。

**本期增量：** 标准库为生产级 RAG（PostgreSQL + Qdrant + Neo4j + 预查询 + rerank）。**本步对话**：每个识别/检查结果及下一步均可自然语言交互（9 页右侧面板，不加第 10 页）；HITL 不写库。

**本期 refine（2026-09-17，仅 `standard_lib`）：** 规范 PDF 登记成功后可点「处理全部页」(`tickAll`)。前端串行循环已有「处理一页」(`tick` / `POST /api/standards/ingest-runs/:id/tick`)，直到没有 `pending` 页。单次 tick 仍 ≤1 页。某一页 `ocr_error` / `index_error` 时继续处理其余 pending，已成功页不回滚。不新增全书一次 OCR 接口。切片仍按条款/表/附件，禁止纯 512 token。

**本期 refine（2026-09-19，仅 `standard_lib`，F-1）：** 检索命中后用户须能读到条文。点击命中行打开 **详情**，展示 `heading` + `body`（表/附件展示可读文本）。出处列（file_name / 页 / unit_id / clause_id / 路径）保留。本步对话引用命中时须带标题与正文，不得只回 `clause_id`。不改检索算法，不加页。

## 目标用户

| 角色 | 职责 |
|------|------|
| 配置人员 | 项目/规范包、模板框选、规则发布、标准库 |
| 操作人员 | 上传 Job、看 findings、组卷预览、审计 |
| 审核人员 | 改 Proposal、确认后出 Receipt |

## 核心流程

1. 创建项目与空规范包  
2. 空白表框选 3 字段并保存模板  
3. 编写 R1/R2，正反例通过后发布  
4. 上传 2 份资料（合规 + 故意颠倒）  
5. 质检 → OCR/文本层 → 按模板抽取  
6. 规则运行时产出 Finding（blocking 拦住自动通过）  
7. 标准符合度：预查询 → 向量或图检索 → rerank → 挂 `clause_id` 再执行阈值/规则  
8. 软措辞进待审，确认后 Receipt  
9. 按用户 groupKeys 组卷预览（不提交）  
10. 用同一 `trace_id` 对账  

**标准库 PDF 入库（仅 `standard_lib`）：** 选择 PDF → `uploadDoc`（`POST /api/standards/ingest-pdf`）得 202 + `ingest_run_id`，各页 `pending` → 可点「处理一页」(`tick`) 或「处理全部页」(`tickAll`，循环 `tick` 至无 pending) → 页状态 `ok` / `ocr_error` / `index_error` 用 StatusTag 展示 → 按条款/表/附件切分入库（检索块不是「整页」）。

**标准库命中阅读（仅 `standard_lib`，2026-09-19）：** 检索 → 出处表列出命中 → **点击行打开详情** → 看到 heading + body → 本步对话可引用该正文。table/annex 的 clause_id 列仍为 —。

## 功能需求

1. C1 配置中心：项目、规范包空壳、模板框选、规则草稿/发布、标准库生产级 RAG（关系/向量/图 + 预查询 + rerank）；`standard_lib` 另提供 `tickAll`（循环 `tick`，非整书一次 OCR）以及命中 **详情**（heading + body）  
2. C2 处理引擎：上传 → 质检 → OCR → 抽取 → 规则 → 待审 → 组卷预览  
3. C3 两层运行时：中台账本；agent-runtime **按步 HITL 对话** + `check_wording`，产出只进 Proposal / interrupt  
4. C4 mock 适配器：无 `receipt_id` 不算写入  
5. C5 APT：`trace_id`、`/verify`、connect-gate

## 数据模型

- Project：项目隔离  
- SpecPack：规范包空壳与版本  
- Template / FieldBox：`page, x, y, w, h, fieldKey, valueType`  
- Rule / RuleVersion：DSL，`draft | published`，发布须正例+反例  
- StandardDoc / StandardVersion：标准文本与生效/废止版本  
- IngestRun / IngestPage：PDF 登记批次与逐页 tick 状态（`pending | ok | ocr_error | index_error`）；`tickAll` 不另建全书 OCR 批次  
- Clause：条款级切分（编号层级、heading、正文 body、span、父条标题）；禁止纯 token 切；检索命中详情读取 heading/body，不把全文塞进每一行表格  
- Chunk：向量库主键对齐 `clause_id`  
- StandardEdge：图边 `CITES | SUPERSEDES | APPLIES_TO | REQUIRES`  
- Job：`uploaded | inspecting | extracting | checking | pending | previewed | failed`  
- Document / Extraction：文件、OCR 文本、抽取 JSON  
- ConversationThread：`trace_id` + `step`；消息进 HITL，不进正式账本  
- Finding：规则命中；`blocking=true` 不得自动通过；标准符合度必须带 `clause_id` + `standard_version` + 原文 span（不得用 LLM 手写条款号）  
- Proposal：认知软结果，默认 pending  
- VolumePreview：预览快照；submit 不对 agent-runtime 开放  
- Receipt：写接口回执  
- AuditEvent：`trace_id` 贯穿  

DSL 子集：`all | any`、`required`、`exists`、`compare`、`regex`、`eq`。

## 非目标

1. 任何专业规则内容（工序日期、应发表份数、成对材料等由用户事后配置；不预置公路/水利/房建规范包）。
2. 口语规则直上生产（只允许 DSL 草稿 + 测试闸门后发布）。
3. Agent / agent-runtime 直连业务库；组卷/建表「提交」类 Tool 不对认知层开放。
4. 资料云解挂/重挂实调、待办回写实调、资料云实挂。
5. Temporal 长流程、私有化大模型、多租户计费、移动端离线、弱网 App。
6. OCR 抽检达标率、Token 年成本承诺。
7. 测表公式、CAD 抽参、模型微调。
8. 引入 LangGraph，或推倒本仓 agent-runtime。
9. 用 Prompt 替代 DSL 硬规则，或用聊天模型当 rerank / 发明条款号。
10. 把 APT 架构索引（`.ai/arch/vectors.db`）当作业务标准库。
11. 一个请求里 OCR/索引完全书（禁止替代逐页 `tick` 循环）。
12. 把切片改成纯 512 token；放宽任务上传 4MB；本轮改其它 8 页。
13. 改检索召回算法；用 Prompt 编造条款正文；把全文塞进每一行命中表；把 table/annex 的 unit_id 写入 clause_id 列。

## 成功标准 / 验收

A1 空规范包无预置公路字样；A2 三框抽取 JSON 含对应 key；A3 缺反例无法 publish；A4 日期颠倒 blocking finding；A5 合规无 R2 finding；A6 待审可改且确认有 receipt；A7 自定义 groupKeys 预览无提交幻觉；A8 认知节点调不到 submit；A9 `trace_id` 串起抽取/规则版本/finding；A10 `/verify` PASS 且 connect `done`。  
A11 条款切分入库；标准符合度 Finding 只挂检索/图命中的 `clause_id`。  
A12 预查询 + 向量召回 + 独立 rerank；同条多问法命中同一 `clause_id`。  
A13 跨条/引用/替代走图查询，返回边路径。  
A14 项目绑定生效版本；废止版不得作现行依据。  
A15 每步可打开 `trace_id`+`step` 本步对话，识别/检查结果可就地提问。  
A16 对话不能覆盖 blocking / submit / 直接 publish；确认后中台才推进。
A17（仅 standard_lib）：登记成功后点「处理全部页」，循环已有 tick 直至无 pending；请求次数 ≥ 页数，且单次 tick ≤1 页。某一页失败时已成功页仍在库，失败页用标签标出，不整本回滚。短文本夹具入库、单页 tick、按条款号检索仍可用。
A18（仅 standard_lib）：检索有命中后，打开详情能看到该条 heading + body（或表/附件的可读文本）；出处列仍在。本步对话回答能引用命中正文，不得只报 clause_id 而声称看不到原文。
