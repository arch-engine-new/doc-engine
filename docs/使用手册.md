# 工程资料核心引擎 · 使用手册

你现在手里的东西，不是「某行业资料管理系统成品」，而是一套 **可教的空引擎**：系统不自带公路 / 水利 / 房建条文。你先教它（项目、模板框、规则、标准条款），它再按你教的去认资料、跑规则、等人确认、给出组卷预览，并用同一条 `trace_id` 把全过程对上账。

当前可打开的交付是 **9 页 Vue 工作台**（`apps/web`），后台是本仓 `packages/core-engine`。配好 `apps/web/.env` 时账本和检索走本机 Docker 三库；不配则仍用进程内存（测试 / CI）。不是资料云生产环境。

## 1. 先建立这张图

```
配置人员「教」                          操作人员「用」                      审核人员「认」
项目 / 空规范包                    上传资料（本期用夹具 Job）              改软措辞
模板上框选字段  ────────────────►  抽取 → 规则检查 → 检查结果  ──────►  确认 Proposal
写 DSL 并发布                         组卷预览（只预览，不提交）              才出 Receipt（正式落库）
标准条款入库 + 检索
                                            ▲
                                            │ 全程同一 trace_id
                                            ▼
                                       审计时间线（只读）
```

右侧每页都有 **本步对话**。消息经 `agent-runtime` 调智谱 GLM 生成回复（配置：仓库根 `.apt/agent-runtime.llm.json`，已 gitignore；无配置时开发/单测用 FakeLlm）。在 `checking` / `pending_review` 等步可说「生成提案措辞」触发 `check_wording`（只写 pending Proposal，不写 Receipt）。在 `checking` / `standard_lib` 等步可请助手查「条款」「规范」：助手**只能**引用检索命中的 `clause_id`；若无命中必须说 **未命中**，禁止编造条款号。对话**不能**改任务状态、不能确认提案、不能发布规则、不能提交组卷。要推进，必须点页面上的独立按钮。

## 2. 现在实际跑在哪

| 层 | 现状 |
| --- | --- |
| 界面 | `apps/web`，Vue 3 + Vite，默认 `http://localhost:5173`（被占用会改 5174） |
| 业务账本 | 有 `apps/web/.env` 时写 **PostgreSQL**；没有 `.env` 时用进程内 SQLite **内存库**（测试 / CI） |
| 标准检索 | 有 `.env` 时走 **Qdrant** 向量 + **Neo4j** 图；没有 `.env` 时走内存向量 / 图端口 |
| 资料文件 | **live + MinIO + PaddleOCR AI Studio** 时可真上传 JPEG/PNG/PDF（4MB 上限，进 MinIO bucket `docengine`）；缺 token 时真上传失败，**夹具**仍可用 |
| 对象存储 | **MinIO**（本机 Docker，API `9000`，控制台 `9001`）——**不是**资料云；`file_uri` 形如 `s3://docengine/jobs/{job_id}/...` |
| OCR | live 且配了 `PADDLEOCR_ACCESS_TOKEN` 时走 **PaddleOCR AI Studio**；内存/CI 用 `FakeOcr`。**有文字层的 PDF** 走 Unicode 抽字（`vendor=pdf-text`，不打 OCR）；**无文本层扫描 PDF** 与 JPEG/PNG 走 `OcrPort` |
| 组卷提交 | 按钮禁用。本期只允许预览，`submitted` 恒为 false |
| 正式写库 | 只认中台 **Receipt**。对话不能写 Receipt。无回执的事件在审计里不算已落库 |

本机 Docker（数据在 `D:\docker_run`）是 live 路径的三库 + MinIO，不是摆设：

- PostgreSQL `docengine-postgres` → `127.0.0.1:5434` / 库 `docengine` / `postgres` / `postgres`
- Qdrant `qdrant` → `http://127.0.0.1:6333`
- Neo4j `neo4j` → Bolt `7687`，网页 `7474`，账号 `neo4j` / `12345678`
- MinIO `minio` → API `http://127.0.0.1:9000`，控制台 `http://127.0.0.1:9001`，默认账号 `minioadmin` / `minioadmin`，bucket **`docengine`**（引擎首次上传时幂等创建）

MinIO 只存**原始上传字节**，供 OCR 回读；**不是**组卷页说的「资料云」/`pending-mount` 正式落库通道。账本里 `Document.file_uri` 记的是 `s3://docengine/jobs/{job_id}/{文件名}`，可在控制台 Objects 里核对。

Vite 只自动加载 `apps/web/.env`，仓库根目录放 `.env` 不会生效。`DATABASE_URL` / `QDRANT_URL` / `NEO4J_*` 四键都空 → 内存模式；live 下缺其中任一 → 启动失败。`MINIO_*` 与 `PADDLEOCR_*` 见 `apps/web/.env.example`：可空；**都空时夹具与单测仍绿，但 live 真上传会 503**。Access Token 只写本机 `apps/web/.env`，不要提交。

## 3. 怎么打开

在仓库根目录。要挂三库时，先把示例环境文件拷过去（只做一次），再起开发服务：

```powershell
cd D:\software\doc-engine
npm install
Copy-Item apps/web/.env.example apps/web/.env
npm run dev -w web
```

不拷 `.env` 也可以 `npm run dev -w web`：进程仍用内存账本和内存检索，和单测 / CI 同一条路。

浏览器打开终端里给出的 Local 地址。顶栏品牌是「工程资料核心引擎」。

第一次进入若任务列表为空，页面会自动调用 **重置演示**。也可随时在「任务」页再点一次。

live 模式下点过 **重置演示** 后，用下面几条确认三库里真有夹具数据（PowerShell；健康检查也可直接用浏览器打开该 URL）：

```powershell
Invoke-WebRequest http://127.0.0.1:5173/api/health
docker exec docengine-postgres psql -U postgres -d docengine -c "\dt"
docker exec docengine-postgres psql -U postgres -d docengine -c "SELECT count(*) FROM t_clause;"
Invoke-WebRequest http://127.0.0.1:6333/collections
docker exec neo4j cypher-shell -u neo4j -p 12345678 "MATCH (c:Clause) RETURN count(c) AS clauses;"
```

`GET http://127.0.0.1:5173/api/health` 在 live 下应返回 `mode` 为 `live`，且 `postgres` / `qdrant` / `neo4j` 为 `ok`。配了 `MINIO_*` 时应有 `minio: ok`（`ensureBucket` 成功）；配了 `PADDLEOCR_ACCESS_TOKEN` 时应有 `ocr: ok`（只做鉴权 GET，不提交 OCR 任务）。未配对应 env 时该项为 `skip`，不是坏了。`\dt` 应列出 `t_*` 表；`t_clause` 行数 > 0；Qdrant `collections` 里应有 `clauses`；Cypher 的 `clauses` 计数 > 0。

没有 `.env` 时 health 返回 `mode: memory`，`postgres` / `qdrant` / `neo4j` / `minio` / `ocr` 均为 `skip`，上面的 docker / collections 命令对应当前网页无效（库可能仍空）。

## 4. 重置演示会种下什么

点 **任务 → 重置演示** 后会种下同一套夹具。live 时先清空 Postgres 本引擎表、Qdrant `clauses` 集合和 Neo4j `Clause` 节点再种；内存模式则换一套进程内库。种完后应有：

1. 项目 **演示项目-夹具**
2. 空规范包（名称就是「空规范包」）+ 模板 **空包模板**，上面 3 个框：`编号`、`日期A`、`日期B`
3. 一段非行业夹具标准 **员工请假说明**（1.1 / 1.2 / 2.1），并绑成生效版本
4. 两条夹具任务：
   - **合规**：日期顺序正常，规则放过
   - **颠倒**：日期A/B 颠倒，规则拦住（blocking）
5. 对颠倒任务自动生成一条 **待审 Proposal**（软措辞，等人确认才出 Receipt）

顶栏「模板 / 规则 / 标准库 / 组卷 / 审计」会跟到这批真实 id。不要手改地址栏里的 `/templates/demo` 一类占位路径。

## 5. 推荐走查顺序（跟着点）

下面是「先看懂产品」的最短路径。每步右侧都可以打开本步对话试一句，例如「这是什么」「下一步做什么」。

### 第一步：任务（主入口）

路径：`/jobs`（打开站点默认就到这）

1. 若列表空或乱了，点 **重置演示**
2. 看两条夹具任务和状态
3. 点一条任务，再点 **检查结果** 链接（或从顶栏进检查页）
4. 需要再跑一遍时：
   - **运行合规夹具**：应无日期颠倒类失败
   - **运行颠倒夹具**：应出现 blocking 失败，并可进入待审
5. **上传资料**（真文件，非夹具）：
   - 点 **上传资料**，选 **JPEG / PNG / PDF**，单文件 **≤ 4MB**
   - live 且 `apps/web/.env` 里 **MinIO 与 `PADDLEOCR_ACCESS_TOKEN` 都配齐** 才会成功；成功后列表出现新 Job，状态会走到 `checking`（或 `failed` 若 OCR/规则拦住）
   - **有文字层的 PDF**：引擎用 Unicode 抽字，审计 `vendor=pdf-text`，不调用 Paddle
   - **无文本层扫描 PDF** 与 JPEG/PNG：走 `OcrPort`（live 为 PaddleOCR AI Studio）
   - 到 MinIO 控制台 `http://127.0.0.1:9001` → bucket `docengine` → 前缀 `jobs/{job_id}/` 应能看到原文件
   - 只配三库、不配 `MINIO_*` / `PADDLEOCR_ACCESS_TOKEN`：夹具按钮仍可用，真上传返回 **503**（不会悄悄用假 OCR）
   - Paddle 队列繁忙（如 code 10010）时文案提示稍后手动重试；轮询超时文案会带 `jobId` 并要求**请勿立即重复提交**。引擎**不会自动重试**

**同意下一步** 才会改 `Job.status`。对话不会改。

任务状态大致是：`uploaded` → `inspecting` → `extracting` → `checking` → `pending` / `previewed` / `failed`。

### 第二步：检查结果（合不合规）

路径：`/jobs/:id/findings`

看抽取字段、Finding 列表。标准符合度若挂了条款，必须带库里的 `clause_id`，不能是模型随口编的条款号。

状态为 `checking` 时，可点 **同意进入待审**（按钮文案以页面为准）。

### 第三步：待审（人确认才算数）

路径：`/pending`

1. 选中重置演示带出来的 Proposal
2. 可 **保存措辞**（仍是待确认）
3. 点 **确认并开 Receipt** —— 这时才有正式回执
4. 不要指望在右侧对话里说「确认」来落库，那不会生效

### 第四步：组卷预览（只看树，不提交）

路径：顶栏「组卷」或 `/jobs/:id/volume`

改分组键（默认 `zone,process`）后点 **写入分组并重预览**。提交按钮是灰的，这是产品约束，不是坏了。

### 第五步：审计（对账）

路径：顶栏「审计」或 `/audit/:traceId`

同一条 `trace_id` 下看事件时间线。只有带 Receipt 的才标成「已落库」。本页对话只读，不能在这里改结论。

### 第六步：配置侧（教引擎）

按顶栏从左到右即可，不必一次做完：

| 顶栏 | 路径 | 你在这页做什么 |
| --- | --- | --- |
| 项目 | `/projects` | 建项目、建空规范包（名称里不能出现公路/水利/房建） |
| 模板 | `/templates/:id/annotate` | 在画布上框字段，保存 3 框；抽取按框投影 |
| 规则 | `/packs/:id/rules` | 写 DSL 草稿；必须有正例 + 反例，**跑夹具通过**才能发布 |
| 标准库 | `/packs/:id/standards` | 入库条款、绑生效版本、加引用/替代边、检索 |

规则页 DSL 子集：`required` / `compare` / `regex` / `eq` / `all` / `any`。缺正例或反例时发布按钮不可用。对话不能 publish。

标准库页可用预填的「员工请假说明」点 **入库条款**，再 **检索**（例如问 `1.1`）。跨条关系用手选条款加边（`CITES` / `SUPERSEDES` / `APPLIES_TO` / `REQUIRES`）。

## 7. 你会觉得「坏了」但其实是设计如此

1. **没配 `.env` 时刷新或重启 dev 后数据没了**  
   这时账本在进程内存里。再点「重置演示」。配了 `.env` 的 live 模式写 Docker 三库，重启网页不会清库；「重置演示」才会清空再种。

2. **右侧聊了「确认 / 发布 / 提交」没反应**  
   对话被禁止做这些事，**不能写 Receipt**。用页面按钮确认提案。

3. **组卷不能提交**  
   提交按钮禁用，本期范围就是预览，`submitted` 仍为 false。

4. **真上传失败或扫描 PDF 报 ocr_error**  
   live 真上传要 **MinIO + PaddleOCR AI Studio token** 同时在 `.env` 里配好。有文字层的 PDF 走 Unicode 抽字（`vendor=pdf-text`）；无文本层扫描件才走 `OcrPort`。没配 token 时用 **夹具** 和文本层标准走查即可。

5. **Docker 里暂时是空的**  
   确认已拷 `apps/web/.env`、三库容器在跑，并在网页上点过 **重置演示**，再用第 3 节的 health / `\dt` / collections / Cypher 命令核。只起 Docker、不拷 `.env` 或不重置，网页仍走内存。

6. **没有公路规范包**  
   故意没有。引擎不预置专业内容。

## 10. Agent 控制面（internal）

运维 / 开发用页面：**`http://localhost:5173/internal/agent-runtime`**（不在顶栏 9 页内）。

| 能力 | 说明 |
| --- | --- |
| 列 run | `GET /api/agent/runs`，含 `graphId=job-step-v1` 的 Job 步编排 |
| 看 trace | `GET /api/agent/runs/:id/trace`，事件含 `run_started` |
| 手动 resume | `POST /api/agent/runs/:id/resume` + `token` + `decision` |

**与 StepChat 的区别：** 右侧「本步对话」可走 `check_wording` 写 pending Proposal、可走只读 `search_clause` 引用命中条款，**不能**确认/submit、**不能**推进 Job。产品页上的 **confirm-next** 与控制面 resume 都经 **`resumeHitl`** 恢复 `waiting_hitl`；无 open HITL 时 confirm-next 返回 **409 `no_open_hitl`**。

agent-runtime 状态落在仓库根 **`.apt/agent-runtime.db`**（已 gitignore）。业务 Job / Receipt 仍在 PostgreSQL 或内存 SQLite，二者不混库。

LLM 配置仍用 **`.apt/agent-runtime.llm.json`**（见 §1）。
