## 1. 一句话目标

两周内，用 APT 协议交付一套 **可教的空引擎**：用户能导入标准、标注模板、编写并发布规则包，系统能对任意上传资料跑通「识别 → 规则执行 → 待审 → 组卷预览」，并用 `trace_id` 对账。

**不在两周内做：** 公路/水利/房建规范包、测表公式、资料云实挂、组卷提交、Temporal、CAD 抽参、弱网 App、模型微调。

验收只验引擎，不验某个专业「管得对不对」。

## 2. 范围冻结

### 2.1 做（核心能力）

| 编号 | 能力 | 两周完成定义 |
| --- | --- | --- |
| C1 | 配置中心（教） | 项目、规范包空壳、模板框选、规则草稿/发布、标准库上传与切片检索 |
| C2 | 处理引擎（用） | 上传 → 质检阈值 → OCR → 按模板抽取 → 规则运行时 → 待审 → 组卷预览 |
| C3 | 两层运行时壳 | 中台接口落库；**agent-runtime** **一个**认知节点，产出只进待审 |
| C4 | 适配器契约 | 资料云写接口 OpenAPI 草稿 + **mock**；无回执不得视为写入 |
| C5 | 工程治理 | APT：契约、connect-gate、`/verify` PASS；全链路 `trace_id` |

### 2.2 不做（明确剔除）

1. 任何专业规则内容（工序日期、应发表份数、成对材料等由用户事后配置）。
2. 口语规则直上生产（只允许 DSL 草稿 + 测试闸门后发布）。
3. Agent / agent-runtime 直连业务库；组卷/建表「提交」类 Tool 不对认知层开放。
4. 资料云解挂/重挂实调、待办回写实调。
5. Temporal 长流程、私有化大模型、多租户计费、移动端离线。
6. OCR 抽检达标率、Token 年成本承诺。

### 2.3 「用户自行训练」的定义（必须写进纪要）

| 训练是 | 训练不是 |
| --- | --- |
| 导入规范 PDF，建立标准库 | 微调 / 再训练基础模型 |
| 在扫描件上框选字段，保存模板 | 靠聊天让模型「学会」P0 对错 |
| 编写 JSON/DSL 规则，附带 ≥1 条测试夹具后发布 | 口头规则未过闸门即生效 |
| 配置组卷键（用户自己的字段名） | 我方预置公路部位/工序键 |
| 改认知节点提示词与示例（软能力） | 用 Prompt 替代规则运行时 |

用户训练质量决定业务对不对；两周交付质量只决定引擎能不能被教。

## 3. 演示主路径（Day 10 必须可点）

准备一份 **与专业无关** 的夹具包（我方自备，不依赖客户公路资料）：

```text
用户创建项目 → 新建空规范包
  → 上传 1 张空白表，框选 3 个字段（如 编号 / 日期A / 日期B）
  → 写 2 条规则并发布：
        R1 必填：编号非空
        R2 顺序：日期A ≤ 日期B
  → 上传 2 份 PDF（1 份合规、1 份故意日期颠倒）
  → 质检 + OCR + 按模板抽取
  → R1/R2 执行：合规件可过；颠倒件产生 finding，拦住自动通过
  → 软措辞进待审，人工可改
  → 按用户配置的组卷键生成预览（不提交）
  → 用同一 trace_id 查到 Job / 规则版本 / 抽取 JSON / 回执
```

夹具规则可以是「收货单」「请假条」级别，**故意不做成工程资料**，以证明引擎与业务解耦。

## 4. 产品页面与数据模型（APT 生成输入）

`generate_prd` 的 `productGoal` 固定为：

> 工程资料核心引擎：教用分离。系统提供模板标注、规则运行时、待审与组卷预览；不预置任何行业规则。正式写库只认中台回执。

### 4.1 页面清单（禁止临时加页）

| pageId | 标题 | 路由 | 类型 |
| --- | --- | --- | --- |
| `project_home` | 项目与规范包 | `/projects` | 列表 + 详情 |
| `template_annotate` | 模板标注 | `/templates/:id/annotate` | 画布框选 |
| `rule_editor` | 规则编辑与发布 | `/packs/:id/rules` | 表单 + JSON |
| `standard_lib` | 标准库 | `/packs/:id/standards` | 上传 + 检索 |
| `job_upload` | 上传与任务 | `/jobs` | 上传 + 状态机 |
| `pending_review` | 待审工作台 | `/pending` | 列表 + 编辑 |
| `check_findings` | 检查结果 | `/jobs/:id/findings` | 只读 + 导出 |
| `volume_preview` | 组卷预览 | `/jobs/:id/volume` | 预览树 |
| `audit_trace` | 审计追踪 | `/audit/:traceId` | 时间线 |

### 4.2 核心实体（中台账本，Agent 不得持有）

| 实体 | 职责 |
| --- | --- |
| `Project` | 项目隔离 |
| `SpecPack` | 规范包空壳（元数据 + 版本） |
| `Template` / `FieldBox` | 页图上的框选：坐标、字段名、类型 |
| `Rule` / `RuleVersion` | DSL + 状态 `draft \| published`；发布必须绑定测试夹具 |
| `StandardDoc` / `Chunk` | 标准库切片与向量 id |
| `Job` | 状态：`uploaded \| inspecting \| extracting \| checking \| pending \| previewed \| failed` |
| `Document` / `Extraction` | 文件、OCR 文本、抽取 JSON |
| `Finding` | 规则命中；`blocking=true` 则不得自动通过 |
| `Proposal` | 认知层软结果，默认待确认 |
| `VolumePreview` | 预览快照；**无 submit 接口对 agent-runtime 开放** |
| `Receipt` | 写接口回执；无回执不算落库 |
| `AuditEvent` | `trace_id` 贯穿 |

### 4.3 两周 DSL 子集（解释器只实现这些算子）

```text
all | any
  required(field)
  exists(field)
  compare(fieldA, op, fieldB)     op ∈ {<, ≤, >, ≥, =}
  regex(field, pattern)
  eq(field, literal)
```

不算两周范围：循环引用、跨文件成对、公式计算、自然语言编译器（NL 只允许生成草稿 JSON，人改完再发布）。

发布闸门：`published` 前必须有 **至少 1 条正例 + 1 条反例** 夹具跑通，否则按钮不可用。

## 6. APT 交付协议（全程强制）

不得绕过 MCP 手搓一套平行工程。主路径：

```text
W0  仓库 + query_project_status 探活
D1  /apt-create 或 generate_prd → generate_frontend_project
    （brief / 风格确认后才生成；可用 --fast 仅当双方书面同意跳过澄清）
D2  apply_blueprint → start_init → 库表设计/apply → register_contract
D3–D7  /feature 按 C1–C4 切片；缺接口写入 connect ledger required-apis=missing
       check_connect_gate: ledger → plan → backend → wire
D8–D9  清 mock（引擎自身 API）、agent-runtime 认知节点
D10 /verify PASS → check_connect_gate stage=done → /apt-accept 演示路径
```

硬约束：

1. 未 `query_contract` 命中的类型，必须 `report_missing`，禁止臆造 API。
2. 写代码后 `audit_arch_changes` → `refresh_asset` / `register_contract`。
3. 宣称完成当天必须 `verify` Overall=PASS，否则不算两周交付。
4. 原型 HTML 不是最终页面；最终以 connect 后的 Vue/React 工程为准。

## 10. 分能力实现要点

### 10.1 模板标注

- 上传页图，前端框选，存 `page, x, y, w, h, fieldKey, valueType`。
- 抽取：OCR 全文 + 框内文本；框失败则该字段 `null`，不中断 Job。
- 两周不做表格线检测、跨页续表。

### 10.2 规则运行时

- 输入：Extraction JSON + RuleVersion。
- 输出：`Finding[]`；`blocking` 由规则标记，默认 `required`/`compare` 为 blocking。
- 执行失败（字段缺失）记 finding，不抛未捕获异常导致 Job 丢失。
- 规则版本写入 AuditEvent，复现时按版本回放。

### 10.3 待审

- 硬规则 blocking finding → Job 不得标为自动通过。
- agent-runtime 认知节点只生成 `Proposal`（`status=pending`）。
- 人点确认后中台写 `Receipt`；模型声称成功无效。

### 10.4 组卷预览

- 用户在规范包里配置 `groupKeys[]`（任意字段名）。
- 引擎按 key 分组、组内按 `orderKey` 排序（可空）。
- 只生成 `VolumePreview` 快照。提交接口可以存在，但 **仅工作台按钮可调**，不进 Tool 白名单。

### 10.5 Mock 适配器

- `POST /adapter/pending-mount` 等返回 `{receipt_id, status}`。
- 契约写入 OpenAPI，后续实挂只换实现，不换中台调用点。

## 11. 验收（只验引擎）

| 编号 | 用例 | 通过标准 |
| --- | --- | --- |

| A6 | 待审 | 软措辞可改；确认后有 receipt |
| A7 | 预览 | 按自定义 groupKeys 分组；无提交成功幻觉 |
| A8 | 白名单 | 认知节点调用 submit 被拒绝或 Tool 不存在 |
| A9 | 追踪 | 任一 Job 可用 `trace_id` 串起抽取、规则版本、finding |

建议客户用自己的一份表、两份扫描件重复 §3。顺序：

5. 配组卷键，只看预览。
