## 1. 结论先行

本平台**可以建成**。必须按「硬规则保底、认知能力增强、长流程可恢复」实施，不能按「一个大模型包办资料全生命周期」承诺。

| 判断 | 口径 |
| --- | --- |
| 现在能做扎实 | OCR / 扫描质检、模板框选抽取、日期与缺项等规则引擎、待审草稿、组卷预览、标准库检索 |
| 能做但须分期 | 口语规则转 DSL（先草稿后发布）、CAD 抽参、等待签章的长流程、弱网 App、多租户 |
| 不宜写入首期承诺 | 零人工归档、模型单独判定真实性、Agent 直写生产库、按「每份 5000 Token」锁定年成本 |

**编排选型（已锁定）：**

- 认知层采用 **自研 agent-runtime**（显式状态图、可打断、Tool 白名单），优于 LangChain AgentExecutor 作为生产主循环。
- 跨天、等待签章的业务长流程采用 **Temporal**（或等价持久化工作流）。二者分工，不互相替代。
- **不使用 OpenCode** 等通用编程 Agent 作为客户生产运行时。
- 待挂、检查、组卷等正式结果 **一律走中台接口落库**；Agent 不直连业务库。

品牌隐喻与架构一致：规则是弓，流水线是箭，验收目标是寻的。

## 2. 背景与建设目标

### 2.1 行业痛点

工程建设资料管理长期存在四类矛盾：

1. **标准繁杂：** 国标、地标、企标更新快，人工核对易错、难追溯。
2. **体量大：** 录入、分类、组卷以人工为主，效率低、一致性差。
3. **合规风险：** 逻辑错误、签章不规范、缺件漏件导致验收受阻。
4. **系统僵化：** 传统软件把规则写死在代码里，难以适配地区与项目差异。

资料云侧已具备填报、组卷、检索、计量/变更/竣工图、日志/旁站等业务能力。缺口主要在 **AI 增强与独立检查工作台**：识别质检、规则化合规、待审草稿、组卷预览提交、可解释检索与模拟验收。本方案定位为 **AI 中台增强**，不替换资料云业务库。

### 2.2 建设目标

建设一套面向工程资料的领域智能平台，核心理念是 **「教」与「用」分离**：

- **教（配置中心）：** 业务人员通过项目上下文、可视化模板标注、自然语言规则草稿、标准库导入，定义「本项目怎么管资料」，换专业换规范包，不改引擎。
- **用（处理引擎）：** 系统完成感知（OCR）、分类、合规检查、缺项草稿、智能组卷；正式生效必须经人确认或电子签章。
- **工程目标：** 生产级可观测、可重试、可对账；支持弹性扩展与项目级隔离；施工弱网作为二期能力预留。

### 2.3 设计原则

| 原则 | 含义 |
| --- | --- |
| 硬约束代码化 | 日期、缺项、成对、闭环、DPI/空白页等 P0 逻辑走规则/公式引擎，禁止用 Prompt 替代 |
| 软能力模型化 | 措辞、建议、问答走 agent-runtime 认知节点；抽检 + 可改 |
| 接口即账本 | 正式写库只认中台回执；模型声称成功无效 |
| 引擎一套、规范包可插拔 | 公路为首期验收主线；水利/房建后挂 |
| 教用分离、发布有闸门 | 口语规则只生成 DSL 草稿，测试通过后才发布 |

## 3. 可行性与范围

### 3.1 可靠性分级

| 级别 | 范围（示例） | 验收目标 |
| --- | --- | --- |
| **P0** | 扫描质检硬阈值、工序日期、质保书与复检成对、缺项清单、建表/组卷/检查结果的接口落库与幂等回执 | 工程级稳定；可回归、可对账 |
| **P1** | 题名润色、整改措辞、目录/单元格建议、小黑板说明、口语规则 DSL 草稿 | 抽检通过率 + 人工可改 |
| **P2** | 语义检索问答、验收解释 | 辅助；以 P0 检查结果为准，对话不是正式台账 |

**P0 不依赖模型「发挥好」。** 认知层故障时，中台任务标记失败并可重跑，不丢账本。

### 3.2 首期专业与 MVP

首期以 **公路** 为验收主线。3–4 个月 MVP 建议锁定为一条闭环：

> 上传识别 → 硬规则合规 → 待审草稿 → 组卷预览

不把「全专业、全自动生成可签章资料、私有化大模型」塞进同一窗口。

### 3.3 与能力清单六大场景的映射

| 场景 | 中台为主（P0） | 认知层为主（经 Tool，P1/P2） |
| --- | --- | --- |
| 纸质数字化归集 | 质检、OCR、待挂/挂载 API、查重指纹 | 著录补全、目录建议、闭合文件提示措辞 |
| 智能辅助填报 | 表样/数据源/公式与测量规则引擎 | 单元格扩写、日志草稿、照片说明草稿 |
| 资料 AI 检查 | 规范/业务规则检测、报告落库与导出 | 意见归纳、整改建议表述 |
| 智能组卷 | 立卷分卷规则、排序编页、组卷提交 API | 案卷题名简化建议 |
| 语义检索与利用 | 索引、元数据、行为链存储 | 自然语言解析与问答 |
| AI 模拟验收 | 完整性/闭环规则编排与结果落库 | 专家视角解释与问答 |

模拟验收 **复用检查规则包**，不另做引擎。完整性默认依据 **应归目录 / 规范包**，不以投资额为默认分类。

## 4. 产品功能架构

### 4.1 智能配置中心（教）

| 能力 | 做法 | 约束 |
| --- | --- | --- |
| 项目上下文 | 录入地区、工程类型、标准体系，加载对应规范包 | 无规范包则不承诺该专业验收 |
| 可视化模板标注 | 空白表扫描件上框选部位、强度、签字栏等，记录坐标与字段类型 | 作为抽取监督信号，可落地 |
| 自然语言规则 | 口语（如「C30 必须测坍落度」）生成 JSON/DSL 草稿 | **测试通过后才发布**；禁止口头规则直上生产 |
| 标准库 | 导入标准文档，切片并建向量索引 | 供 RAG 比对条款，不替代规则引擎 |

### 4.2 智能处理引擎（用）

流水线：

```text
感知 OCR / PDF / CAD 抽参
    → 类型识别与模板关联
    → 规则合规（完整性 · 逻辑性 · 标准符合度）
    → 缺项草稿（待审核）
    → 组卷预览
    → 确认后接口一次性提交
```

- **完整性：** 必填项、应有表份数（规范包）。
- **逻辑性：** 工序先后、日期、桩号；失败则拦住自动写入。
- **标准符合度：** RAG 检索条款，比对实测；条款命中可解释，超标判定以规则/阈值为准。
- **缺项生成：** 只出草稿并标记「系统生成待审核」，责任人确认或电子签章后生效。
- **组卷：** 部位聚合预览；确认后一次性提交。落地依赖档案系统 **解挂 / 重挂** 或等价接口。
- **测表：** 中台公式引擎计算，LLM 只解释；公式由客户提供。
- **日志：** 硬字段可写，正文待确认。
- **图纸：** CAD + PDF 抽参；一期元素含尺寸、标高、桩号、材质、厚度、坡度、坐标、构件编号；抽检阈值可配。

### 4.3 写回策略

| 类型 | 默认策略 |
| --- | --- |
| 硬规则通过 | 可自动落库（仍走中台接口，留审计） |
| 软结果（措辞、建议、正文草稿） | 待确认后生效 |
| 应发表包、组卷 | 中台预览后一次性提交，不对认知层开放「直接提交」Tool |

### 4.4 查重与指令闭环

- **查重：** MD5（全同）+ 感知哈希 / 文本指纹（再扫重复）+ 同名版本。禁止只靠 MD5。
- **指令 ↔ 整改：** 文号优先；其次主题 + 项目 + 时间窗；再次赋码。低置信待确认。

## 5. 总体技术架构

### 5.1 DDD 分层

| 层 | 职责 |
| --- | --- |
| 接入层 | API 网关：鉴权、限流、路由、TLS |
| 应用层 | 无状态服务：工程、配置、资料处理、组卷、检查工作台 |
| 领域层 | 合规、组卷方案、提案状态等业务语义，不含 OCR / LLM 细节 |
| 基础设施层 | MySQL、Redis、对象存储、向量库、OCR、LLM 网关、Temporal、agent-runtime |

### 5.2 两层运行时（必须坚持）

```text
┌──────────────────────────────────────────────────────────┐
│  资料云工作台 / 批调度 / 其他业务系统                       │
│            │ HTTP/API                                    │
│            ▼                                             │
│  ┌────────────────────────────────────────────────────┐  │
│  │  中台 = 业务控制面（可含 Temporal）                   │  │
│  │  · 任务队列与状态机                                   │  │
│  │  · 硬规则 / 公式引擎                                  │  │
│  │  · 识图流水线（质检 CV / OCR / 可选 VL）              │  │
│  │  · 待挂 / 检查 / 组卷 等业务 API（唯一正式落库入口）   │  │
│  │  · 权限、审计、幂等、trace_id                         │  │
│  │  · 适配器 → 资料云 / OSS / 原系统                     │  │
│  └─────────────┬──────────────────▲─────────────────────┘  │
│                │ Tool / MCP 薄封装 │ 回执 / 状态查询         │
│                ▼                  │                        │
│  ┌────────────────────────────────────────────────────┐  │
│  │  agent-runtime = 认知编排层（自研图工作流运行时）       │  │
│  │  · 显式状态图、人工 interrupt、检查点                 │  │
│  │  · Tool 白名单 + JSON Schema                          │  │
│  │  · 题名 / 目录建议 / 检查意见 / 检索问答              │  │
│  │  · 不持有正式业务账本                                 │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

**一句话：** 中台保证「必须对」；agent-runtime 提升「猜得对更好」；落库与追责只认中台接口回执。

识图与 OCR 在中台完成；编排模型可以是纯文本 / 编码模型，不依赖「识图窗口」。MCP（或等价 Tool）薄封装同一套 HTTP，工作台与批任务共用契约，禁止两套业务逻辑。

### 5.3 为何用自研 agent-runtime 而不是 LangChain Agent

| 组件 | 用途 | 不用于 |
| --- | --- | --- |
| **agent-runtime** | 认知图：循环、分支、人工 interrupt、检查点、Tool 白名单 | 跨月等待签章的主账本 |
| **Temporal** | OCR → 合规 → 待审 → 组卷的长事务；宕机续跑 | 替代 LLM 推理 |
| **LlamaIndex / 向量库** | 标准库切片与混合检索 | 日期对错的最终判决 |
| **LangChain** | 模型与部分工具适配（胶水） | 生产主循环（AgentExecutor） |

自研 agent-runtime 比 LangChain 传统 Agent 更适合生产：状态显式、可打断、可测、可限制 Tool，且不绑定上游图引擎版本。Temporal 解决「等签字可能数天到数月」——这是 agent-runtime 检查点解决不了的业务持久化问题。

MVP 可用 Redis 队列先跑通，工作流接口按 Temporal 语义预留，避免推倒重来。

### 5.4 逻辑拓扑

```text
Web / 移动端（可离线拍照，二期）
    → API 网关（RBAC · TLS · 限流）
        → 应用服务（无状态）
            → Temporal（长流程账本）
                → 规则 / 公式引擎
                → 识图 / OCR
                → agent-runtime（认知节点 + 白名单 Tools）
                    → RAG（标准库）
                    → 提案 API
                    → LLM 网关（国产主备）
            → MySQL · Redis · OSS · Vector · 电子签 CA
            → 资料云适配器（目录 / 挂载 / 解挂重挂 / 待办）
```

### 5.5 关键设计约束

1. 写接口 **幂等**；状态仅成功 / 失败 / 处理中 / 待人工。
2. **`trace_id`** 贯穿任务 → agent-runtime run → Tool → 资料云。
3. 模型声称成功无效，**只认回执**。
4. 提交类动作（建表包、组卷、硬字段写入、公式计算）**不对 agent-runtime 开放**。
5. 批量主路径优先短任务编排（按文件或小批），避免超长无边界自主循环。
6. 组卷落地依赖资料云解挂 / 重挂；缺接口则对应能力只验预览、提交补验。

## 6. 生产级保障

### 6.1 并发与扩展

耗时步骤异步化，前端返回任务 ID，接口响应目标小于 200 ms。交互队列与批处理队列隔离。Worker 无状态，可按队列深度水平扩展（如 Kubernetes HPA）。

### 6.2 可靠性

Temporal（或等价引擎）支持长暂停与断点续传。agent-runtime 认知步失败只失败认知步，中台任务可重跑，不丢账本。超时与半成功必须落在四种状态之一，禁止静默丢单。

### 6.3 弱网

移动端离线拍照与本地草稿，恢复后断点续传。属二期能力，不阻塞公路闭环 MVP。

### 6.4 日志、安全与合规

| 类别 | 要求 |
| --- | --- |
| 技术日志 | JSON + `trace_id` |
| 业务审计 | 谁、何时、对哪份资料、做了什么 |
| Agent 日志 | Prompt、输出、Token，用于成本与调优；按保留期归档 |
| 权限 | RBAC 到项目–角色–操作；多项目隔离 |
| 传输与存储 | TLS；敏感字段加密 |
| 电子签 | 接入符合《电子签名法》的第三方 CA |
| 数据出境 | 按采购合同；模型不得用于未经授权的训练 |

## 7. 模型与成本

### 7.1 选型

国产主备 + 网关路由：高频抽取用低价模型（如 GLM-Flash / Qwen Turbo），复杂推理用 Plus 级。不绑单一厂商。识图与编排可分模型。客户指定或自备内网模型均可接入网关。

### 7.2 成本口径（修订）

按量调用远低于自建 GPU，方向正确。原稿「100 万份 × 5000 Token → FlashX 年成本约 500 元」在算术上可成立，但 **真实单份通常含多页 OCR 与多段 RAG，Token 会明显高于 5000**。商务数字须用样例实测后再写入合同，不把 500 元/年作为承诺。

Token / 云资源费用默认 **不含在开发合同内**，除非商务另约。

### 7.3 部署路径

| 阶段 | 形态 | 说明 |
| --- | --- | --- |
| 阶段一 | 公有云按量 API | 推荐起步；网关可切换厂商 |
| 阶段二 | 客户 VPC 私有化开源模型 | 数据不出域时评估；**不作为 MVP 前置** |

## 8. 实施路线

| 阶段 | 周期 | 交付 |
| --- | --- | --- |
| 前置 | 约 2 周 | 公路规范包、样例、接口对照（含组卷解挂/重挂是否具备） |
| 第一阶段 | 3–4 个月 | 公路闭环：识别、硬规则合规、待审草稿、组卷预览；agent-runtime 认知节点；Redis 队列 + Temporal 接口预留 |
| 第二阶段 | 6–8 个月（含上一阶段） | Temporal 长流程、RBAC、全链路日志、NL 规则发布闸门、并发隔离 |
| 第三阶段 | 12 个月+ | 多专业包、检索与模拟验收增强、私有化评估、弱网 App |

**客户关键路径：** 规范包、测表公式、资料云写接口、解挂重挂。缺接口则对应能力只验预览、提交补验。

波次建议：先打通 **归集 + 检查落库**（中台与认知层联调），再填报、组卷提交、检索与模拟验收。认知层首波建议从 **检查措辞**（`check_wording`）切入，不把写库 Tool 放进首波。

## 9. 验收建议（公路样例）

1. 扫描质检硬阈值可回归（DPI、空白页、明显倾斜）。
2. 故意颠倒工序日期，系统拦住自动写入。
3. 检查报告可导出或回写待办；措辞可改。
4. 组卷预览：同部位工序不得拆到互不相邻卷。
5. agent-runtime 无法调用「组卷提交」类 Tool（白名单测试）。
6. 全链路可用 `trace_id` 追查到中台回执。
7. 查重：全同文件与再扫近似件均能检出，不只靠 MD5。
8. 无公路规范包时，系统明确拒绝「该专业可验收」承诺。

---

## 10. 风险与边界

| 风险 | 应对 |
| --- | --- |
| 把大模型当规则引擎 | P0 代码化；合同与验收按分级，不按「智能程度」验收 |
| 资料云缺解挂/重挂 | 组卷只验预览；提交作为接口到位后的补验项 |
| NL → DSL 误发布 | 草稿 + 用例闸门；无测试通过不得上生产 |
| Token 成本被低估 | 样例实测后再报价；开发合同与推理费用分离 |
| 专业范围膨胀 | 首期只锁公路；其他专业以规范包接入，不改引擎 |
| 运行时选型混用 | 对客口径统一为：中台控制面 + agent-runtime 认知层 + Temporal 长流程 |

**明确不做（本方案下）：**

1. 以通用编程 Agent 作为客户生产运行时。
2. Agent 或脚本绕过中台直连数据库写待挂 / 检查 / 组卷。
3. 仅靠 Prompt 约束替代 DPI / 空白页 / 日期逻辑等硬规则。
4. 第一期承诺「全自动归档零人工、零误差」。
5. 将 Token / 云资源费用默认含在开发合同内。

---

## 11. 总结

本方案是可进化的工程底座，而不是一次性套装软件。

- **业务：** 教用分离，配置驱动适配；引擎一套、规范包可插拔。
- **技术：** 规则拉弓，agent-runtime 瞄准认知，Temporal 保证长流程不丢；落库只认接口回执。
- **成本：** 按量国产模型；用实测 Token 定价。
- **安全：** RBAC、加密、合法电子签、全链路审计。

锐指向可按第一阶段范围组织设计与落地。建议与能力清单、资料云接口清单、公路样例资料一并作为下一轮对齐输入。
